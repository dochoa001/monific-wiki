PASO 1 · Clasificación del Proyecto (HUBSPOT)
Al iniciar un proyecto o una nueva campaña, deben llenarse las siguientes propiedades en el Objeto "Negocio" (Deal/Proyecto):
Tipo de Proyecto: Solid (Aforo ≥ 1.5 + Garantía Real) / Estándar (Legacy).
Tipo de Rendimiento: Fijo / Variable.
Aforo Inicial: (Ej. 1.8)
Garantía Líquida: Sí/No.
Monto de Garantía Líquida: $ (Si aplica).
Tasa Moratoria: 38% (Default para Solid).
Comisión Pago Tardío: 15% (Default para Solid).
Plazo: En caso de tener se ponen los meses.
Rendimiento fijo anual:
Fecha de próximo pago
Legacy serán los primeros proyectos de Monific con garantías menos robustas que las que existen hoy.

PASO 2 · Cobranza preventiva (automatización)
Sistema
HubSpot monitorea la propiedad:
Fecha_de_Pago_Próxima
Workflow de recordatorios
T-10 → Email automático al Solicitante
T-7 → Email automático al Solicitante
T-5 → Email + Whatsapp automático al Solicitante
Mensaje base
“Te recordamos que el pago del proyecto [Proyecto] vence el [fecha].”
Checkpoint automático
Propiedad:
Pago_Registrado = Sí / No
Si Pago_Registrado = Sí
El ciclo se marca como cumplido.
HubSpot reprograma el siguiente periodo.
Fin del ciclo.

PASO 3 · Activación de cobranza humana
Disparador
T-5 y Pago_Registrado = No
Sistema
HubSpot crea tarea a Guillermo:
“Iniciar cobranza preventiva manual”
Acciones de Guillermo
T-5 → Contacto manual al Solicitante
T-3 → Contacto manual al Solicitante
T-2 → Contacto manual al Solicitante + Obligados Solidarios
Día 0 → Contacto manual al Solicitante + Obligados Solidarios
Mensaje clave (T-2 y Día 0)
“Hola [Dueño/Socio], el pago del proyecto [Proyecto] vence en menos de 48h.
Evita la comisión automática por pago tardío.”

PASO 4 · Fecha límite efectiva
Sistema
HubSpot valida:
Fecha_de_Pago_Próxima es hábil / inhábil
Si es inhábil
La fecha límite se recorre al siguiente día hábil.

PASO 5 · Checkpoint final (Día 0)
Sistema
HubSpot crea tarea a Guillermo:
“Confirmar pago o promesa de pago”
Propiedad clave
Pago_Confirmado = Sí / No
Regla
Hora límite: 6:00 PM del Día 0 (fecha límite efectiva)

PASO 6 · Evento de Incumplimiento (Día 1)
Disparador
Pago_Confirmado = No después de las 6:00 PM del Día 0
Sistema
HubSpot marca:
Estatus_del_Proyecto = Incumplimiento
Fecha_de_Incumplimiento = Día 1

PASO 8 · Clasificación del incumplimiento
Sistema
HubSpot evalúa:
Tipo_de_Incumplimiento = Rendimientos / Capital

PASO 9A · Incumplimiento de rendimientos
Si Existe_Garantía = Sí
HubSpot asigna el caso a Ted.
Emiliano + Vian validan tipo de garantía.
Si Garantía_Líquida = Sí
Finanzas usa la reserva para cubrir el rendimiento.
HubSpot marca:
Garantía_Usada = Sí
Solicitante_Bloqueado = Sí
Si Garantía_Líquida = No
Continúan moratorios.
Se prepara expediente legal.
Se ejecuta garantía.

PASO 9B · Incumplimiento de rendimientos sin garantía
Acción
Gestión directa / negociación.
Resultado
Si se regulariza → regresa a ciclo normal.
Si no → reestructura o salida.

PASO 10 · Incumplimiento de capital (pre-vencimiento)
Disparador
Dias_Para_Vencimiento ≤ 90
Sistema
HubSpot dispara:
Revaluación de aforo.
Decisión
Si Aforo ≥ 1.5 : 1
Solicitar fuente de repago.
Si Aforo < 1.5 : 1
Exigir refuerzo de garantía o prepago parcial.

PASO 11 · Refinanciamiento
Condición
Fuente de repago no consolidada.
Acción
Solicitud formal de refinanciamiento.
Resultado
Aprobado → nuevo calendario.
Rechazado → margen limpio para ejecutar garantía.

PASO 12 · Incumplimiento de capital post vencimiento
Acción
Con garantía → ejecución.
Sin garantía → estrategia de recuperación.

PASO 13 · Comunicación a inversionistas
Responsable
Raquel
Si hubo garantía líquida
“Se activó la garantía. Tu rendimiento se pagará conforme al calendario.”
Si no hubo garantía líquida
“Se inició el proceso de cobranza con respaldo patrimonial.”

SLAs, Guidelines y Escalamientos para Cobranza
1. PRINCIPIOS
Día 1 = Incumplimiento
No hay “periodos de gracia”.
Si no pagó en fecha límite efectiva → incumple.

La automatización abre el camino, el humano cierra
HubSpot presiona.
Guillermo confirma.
Legal ejecuta.

2. SLAs POR FASE

T-7

Objetivo: Confirmar pago o promesa real.
SLA crítico
Hora límite de validación: 6:00 PM

Pago_Confirmado = Sí / No

Guillermo

SLA del sistema

Comisión 15% + IVA
Interés moratorio activo
SLA de notificación
Notificación formal a:
Solicitante

Pausas

Reasignaciones
Seguimientos
Nunca escala.

🟡 NIVEL 1 · ATC
Resuelve sin pedir permiso:
Dudas operativas
Quejas leves
Atrasos explicables
Recomendaciones de proyectos
Clientes indecisos
Si puede resolverse con fragmentos o subiendo tickets → se resuelve.

El cliente insiste más de 3 veces
Hay riesgo de abandono
El mensaje empieza a ser hostil
Hay inconsistencia operativa

✔ Posible UNE / CNBV
✔ Impacto colectivo
